## 概要

本実験では、[Jev 向けのプロンプト作法](../docs/source-of-truth/jev-prompt-guide.md)がどの程度効くかを、3 課題（Choice / Score / Noul）× 8 条件で測った。事前に立てた仮説は次の 4 つである。

1. 一般的な LLM 向けの書き方を移植すると、精度が落ちる（H1）
2. プロンプトのどの要素を崩すかで、精度の落ち方は違う（H2）
3. 良いプロンプトほど、確信度の高い誤答が少ない（H3）

事前に宣言した判定規則による結果は、H1 は棄却、H2 は課題ごとに異なる、H3 は棄却、H4 は判定不能である。ただし、規則の外側の数値まで含めると、次のように読むのが妥当である。

**H1** は、Score では合格ラインを超えた（MAE 0.501 対 0.733）。Noul は主指標の AUC では差が小さかったが、閾値 0.5 での正解率では A が 26.7 ポイント高かった。Choice はどの書き方でも精度がほぼ同じだった。

**H2** では、崩す要素によって精度の落ち方が大きく異なった。

| 課題 | 崩すと精度が大きく落ちた要素 | 差を検出できなかった要素 |
| --- | --- | --- |
| Choice（順序なし多値分類） | なし | 選択肢の説明、質問文、判断に関係ない入力 |
| Score（順序あり分類） | 段階の定義（数字や程度語にすると MAE が約 0.23 悪化） | 質問文。判断に関係ない入力は有意だが小さい（MAE +0.036） |
| Noul（二値分類） | なし | 条件の定義、判断に関係ない入力 |

**H3** は、確信度の高い誤答が Jev のほぼ全条件で 0〜2 件しかなく、規則による比較がほとんど意味を持たなかった。較正誤差（ECE）で見ると、A は 3 課題とも Jev の条件の中で最も小さい（Choice は同率）。

## 1. はじめに

この報告は、Jev のプロンプト作法の効果を知りたい人に向けたものである。実験の設計手順、合格ライン、ケースの切り方は[評価設計書](../docs/source-of-truth/design-of-evaluation.md)にある。

Jev は、判断材料（state）と質問の集合（instructions と criteria）を入力とし、コードがそのまま使える型付きの判断とその確率を出力とする。[プロンプトガイド](../docs/source-of-truth/jev-prompt-guide.md)には、state、instructions、criteria をどう書くかがまとめてある。本実験は、その作法が精度と確信度にどれだけ効くかを測った。

事前に立てた問いは次の 3 つである。

1. LLM 流の書き方を移植すると、Jev 用に書いた場合より精度が落ちるか（H1）
2. 崩す要素によって、精度の落ち方は違うか（H2）
3. 良いプロンプトほど、確信度の高い誤答が少ないか（H3）

## 2. 方法

3 課題 × 8 条件を、同じケースで比べる対応のある比較である。

### 2.1 課題とケース

| 課題 | タイプ | データ | 何を判定するか |
| --- | --- | --- | --- |
| Choice | 順序なし多値分類 | BANKING77 | 銀行の顧客問い合わせの意図（77 種） |
| Score | 順序あり分類 | Amazon ESCI | 検索語と商品の関連度（無関係・補完・代替・一致） |
| Noul | 二値分類 | SMS Spam Collection | SMS がスパムかどうか |

Score の正解は、ESCI のラベルを I(irrelevant) = 0、C(complement) = 1、S(substitute) = 2、E(exact) = 3 の段階に対応させたものである。この順序は KDD Cup の利得の順に従う約束事であり、厳密な順序尺度ではない。

各課題 100 件を、ランダムに選んだ 50 件と、混同しやすい境界ケース 50 件で構成した。これを正解ラベルで層化して dev 40 件と test 60 件に分けた。本報告の数値はすべて test 60 件のものである。

### 2.2 条件

基準は、ガイドに沿って書いたプロンプト A である。B1〜C は A から 1 つの要素だけを変え、L1〜L3 は比較用の LLM である。

| 条件 | 変えるもの | 内容 |
| --- | --- | --- |
| A | （基準） | ガイドに沿った書き方 |
| B1 | instructions と criteria | LLM 流。指示を曖昧な 1 文にし、選択肢の説明を名前だけにする |
| B2 | criteria のみ | 選択肢・段階・条件の定義を崩す |
| B3 | instructions のみ | 質問文を崩す |
| C | state のみ | 判断に関係ない情報を足す |
| L1 | 比較用 LLM(openai/gpt-5.6-luna) | 素朴な指示 |
| L2 | 比較用 LLM(openai/gpt-5.6-luna) | 整備した指示（定義、JSON スキーマ、few-shot 3 件） |
| L3 | 比較用 LLM(anthropic/claude-sonnet-5) | L2 と同じ指示で、モデルだけを変える |

各条件で実際に何を変えたかは、課題によって異なる。考察で重要になるため、要点を次に示す（正本は [prompts/](../prompts/README.md) の JSON）。

| 条件 | Choice | Score | Noul |
| --- | --- | --- | --- |
| A | 77 意図と `other`。混同しやすい意図に `what` / `not_for` / `examples`、残りは 1 行の説明。質問文は `query` をパスで指す | 4 段階をそれぞれ状況として記述（無関係、一緒に使う別の品、代わりになる別の品、指定の属性をすべて満たす品） | 「求められずに届いた商用または詐欺的なメッセージか」。criteria の true は「広告・勧誘・金銭や情報の要求」 |
| B1 | 質問文を "Analyze this customer message and determine what they need." に、説明をすべて `null` に、`other` なし | 質問文を "Rate how relevant this product is." に、段階を `"1"`〜`"4"` に | 質問文を "Check this message and decide whether there is a problem with it." に、criteria なし |
| B2 | 説明を "Card issues" などの大分類に置き換え、`other` なし | 段階を "not relevant" 〜 "highly relevant" の程度語に | criteria の true を「勧誘されておらず、かつ金銭や個人情報を求める」という AND 条件に |
| B3 | 質問文を "What is the underlying need behind the issue the customer is ultimately describing?" に（間接的、パス指定なし） | 質問文に「関連性・レビューの質・価格」の 3 次元を入れる | 質問文を "Is `message` free of any unsolicited commercial content?" に（否定形）。criteria は A のまま |
| C | 約 2,000 トークンの規約文などを state に追加 | 箇条書き、ブランド、色、他候補 3 件を state に追加 | 端末情報、受信時刻、無関係な過去の受信 5 件を state に追加 |

### 2.3 モデルと実行

Jev は `typesafe/jev-1.13`、L1 と L2 は `openai/gpt-5.6-luna`、L3 は `anthropic/claude-sonnet-5` を、いずれも OpenRouter 経由で呼んだ。LLM は `{"label": ..., "confidence": ...}` の JSON を返し、その確信度は自己申告の数値である。Jev の確信度は、Choice と Score では確率分布の集中度から計算される値で、Noul では `noul` の値から決まる。

実行は、ケースごとに全条件を連続で回した。呼び出しの失敗とパースの失敗は不正解として数え、その割合を `error_rate` として付録に示す。

### 2.4 指標

主指標は、Choice が top-1 精度、Score が正解の段階との MAE（`score` は丸めない）、Noul が AUC（反転を補正しない）である。共通指標は、確信度の高い誤答率、ECE、1,000 件あたりトークン、レイテンシの p50 と p95 である。

結果の表に出る列の意味は次のとおりである。

| 列 | 意味 |
| --- | --- |
| top1 | Choice で、最も確率の高い意図が正解と一致した割合 |
| mae | Score で、出した値と正解の段階との差の絶対値の平均。値は四捨五入しない。小さいほど近い |
| spearman | Score で、出した値と正解の段階の順位がどれだけ一致するか。1 に近いほど順位が合い、負なら逆 |
| auc | Noul で、スパムの方がスパムでないものより高い値になる割合。0.5 は区別できず、1 は完全に分かれ、0 は完全に逆向きに分かれる |
| CI | その指標の 95% 区間。同じケースを再標本したときのばらつき |
| confident_error_rate | 確信度が 0.9 以上なのに誤った割合。Noul は値が 0.1 以下または 0.9 以上のとき、確信度が高いとみなす |
| ece | 確信度を 0.1 刻みの区間に分け、区間内の正解率との差を件数で重みづけした平均。0 に近いほど、確信度が正解率と一致する |
| tokens_per_1000 | 1 件あたりの使用トークン数の平均を 1,000 倍した値。1,000 件ぶんのトークン数 |
| latency_p95_ms | 応答時間（ミリ秒）を短い順に並べたとき、95% の位置の値。これより遅いのは全体の 5% |

同じケースを 2 条件で比べるときは McNemar 検定、指標の区間はブートストラップ（10,000 回、95%）、A 対各条件の多重比較は Holm 補正を使う。読み方は[統計手法の解説](../docs/statistical-methods.md)にある。

### 3.2 LLM 流プロンプト使用時の精度（H1）

H1 は「一般的な LLM 向けの書き方をそのまま移植すると、Jev 用に書いた場合より精度が落ちる」である。事前に宣言した規則は、3 課題のうち 2 課題以上で A が B1 を合格ライン以上に上回り、かつ A の確信度の高い誤答率が B1 の半分以下であれば支持、というものである。

| 課題 | 主指標 | A | B1 | A の優位 | 合格ライン | 通過 |
| --- | --- | --- | --- | --- | --- | --- |
| Choice | top1 | 0.900 | 0.933 | -0.033 | +0.05 以上 | しない |
| Score | MAE | 0.501 | 0.733 | +0.232 | +0.2 以上 | する |
| Noul | AUC | 0.999 | 0.962 | +0.037 | +0.05 以上 | しない |

確信度の高い誤答率は、Choice で A 0.033・B1 0.000、Score と Noul で両条件とも 0.000 だった。

主指標の差が合格ラインを超えたのは Score だけなので、判定は棄却である。ただし、Noul の閾値 0.5 での正解率は、A が B1 を 0.267 上回った（区間 [0.133, 0.400]、Holm 補正後 p = 0.002）。

B2、B3、C の A からの悪化量を示す。正の値ほど A より悪い。Choice と Noul は A − 各条件、Score の MAE は各条件 − A である。区間と p 値は付録の「A 対 他条件」による対応ありの推定で、点推定は表の値から計算したものと小数第 3 位で異なることがある。

| Choice（top1） | B2 | -0.050 | [-0.117, 0.017] | 1.000 |
| Choice（top1） | B3 | 0.000 | [0.000, 0.000] | 1.000 |
| Choice（top1） | C | 0.033 | [0.000, 0.083] | 1.000 |
| Score（MAE） | B2 | 0.242 | [0.137, 0.346] | 0.000 |
| Score（MAE） | B3 | -0.001 | [-0.032, 0.028] | 0.962 |

有意な悪化は、Score の B2 と C である。Score の C は有意だが、悪化量は 0.036 と小さい。

### 3.4 確信度（H3）

H3 は「確信度は誤答の予測子として使える。良いプロンプトほど確信度の高い誤答が少ない」である。

| 条件 | Choice 誤答率 | Choice ECE | Score 誤答率 | Score ECE | Noul 誤答率 | Noul ECE |
| --- | --- | --- | --- | --- | --- | --- |
| A | 0.033 | 0.052 | 0.000 | 0.087 | 0.000 | 0.045 |
| B1 | 0.000 | 0.064 | 0.000 | 0.218 | 0.000 | 0.130 |
| B2 | 0.000 | 0.072 | 0.000 | 0.280 | 0.000 | 0.068 |
| B3 | 0.017 | 0.052 | 0.000 | 0.138 | 0.883 | 0.895 |
| C | 0.017 | 0.052 | 0.000 | 0.101 | 0.000 | 0.056 |
| L1 | 0.000 | 0.047 | 0.383 | 0.434 | 0.083 | 0.072 |
| L2 | 0.000 | 0.066 | 0.133 | 0.129 | 0.017 | 0.032 |
| L3 | 0.000 | 0.141 | 0.017 | 0.089 | 0.000 | 0.056 |

「誤答率」は確信度の高い誤答率である。事前の規則（A の確信度の高い誤答率が B1 より小さいか）では、Choice で A が B1 を上回ったため棄却である。

規則の外側では、次の 2 点が観測された。
1 つ目に、Jev の確信度の高い誤答は、Noul の B3 を除くすべての条件で 0〜2 件だった。
2 つ目に、ECE は Jev の条件の中で A が Score と Noul で最小、Choice で同率最小だった。
確信度の区間ごとの正解率は付録の較正表にある。

## 4. 考察

### 4.1 本章の位置づけ

事前に宣言した規則では、H1 と H3 は棄却された。本章では、規則の外側で目立った較正誤差（ECE）に焦点を当てる。ただし ECE は事前の主指標ではなく、結果を見てから選んだ観点である。したがって本章の内容は探索的な所見であり、次の実験で検証すべき仮説として扱う（4.5 節参照）。

### 4.2 ガイドに沿ったプロンプトは確信度の信頼性を高める

A の ECE は Choice 0.052、Score 0.087、Noul 0.045 だった。Jev の 5 条件の中では、Score と Noul で最小、Choice で同率最小である。3 課題すべてで 0.1 を下回った条件は A だけだった。ただし 0.1 という線は事後に引いたものであり、C の Score（0.101）はほぼ境界上にある。

| 条件 | Choice ECE | Score ECE | Noul ECE |
| --- | --- | --- | --- |
| A | 0.052 | 0.087 | 0.045 |
| B1 | 0.064 | 0.218 | 0.130 |
| B2 | 0.072 | 0.280 | 0.068 |
| B3 | 0.052 | 0.138 | （評価不能、4.5 節） |
| C | 0.052 | 0.101 | 0.056 |

差の大きさは課題によって違う。Choice では条件間の差が 0.02 程度しかない。60 件・10 区間という規模では、この程度の差は標本のばらつきで説明できる。意味のある差として読めるのは、Score の B1・B2（A の 2.5〜3 倍）と Noul の B1（約 3 倍）である。

これらの悪化は、どれも同じ形をしていた。中程度の確信度で、正解率が確信度を大きく下回るという形である。

- Score B1：確信度 0.4〜0.5 の 15 件の正解率は 0.133 だった。A では同じ帯の確信度と正解率がほぼ一致している（例：0.5〜0.6 帯で確信度 0.534、正解率 0.556）。
- Score B2：確信度 0.4〜0.8 の 27 件の正解率は 0.26 だった。
- Noul B1：確信度 0.5〜0.6 の 9 件の正解率は 0.222 だった。0.5 を下回っているので、これらは「少し自信があって外れる」のではなく、系統的に反対側に倒れている。

一方で、順位で測る指標はほとんど落ちていない。Score の Spearman は A 0.618、B1 0.636、B2 0.616 でほぼ同じだった。Noul B1 の AUC も 0.962 と高い。しかし閾値 0.5 での正解率は A より 26.7 ポイント低い。つまり B1・B2 では、ケースの並び順はほぼ保たれ、値の絶対位置、つまり境界がどこにあるかがずれた。ECE は、この「境界のずれ」を捉えた指標だといえる。

較正表から逆算した正解率（Score は、丸めた値が正解の段階と一致した割合）は、A 0.62、B1 0.37、B2 0.42 だった。段階の定義を崩すと、MAE だけでなく、段階を当てる率そのものも大きく落ちている。

### 4.3 実務上の意味

確信度が較正されていれば、確信度の高いものは自動で処理し、低いものを人に回すといった運用が組める。A ではこれが実際に成り立っていた。

- Noul A では、確信度 0.8 以上の 55 件がすべて正解だった。B1 では 34 件中 29 件だった。
- Score A では、確信度 0.8 以上の 17 件がすべて正解だった。

Jev の値そのものの精度はプロンプトによってあまり変わらない。しかし、その値をどこまで信じてよいかは、プロンプトによって変わる。これが本実験で最も実用的な所見である。

また、A の較正は LLM 条件と比べても遜色がなかった。Score では L3（0.089）と同程度で、応答時間の中央値は約 1/10 だった（168 ms 対 1,755 ms）。ただし Noul では L2（0.032）の方が小さく、A が全条件で最良というわけではない。

### 4.4 Jev における良いプロンプト

以上から、「結局、良いプロンプトとはどんなものか」への現時点の答えは次のとおりである。一言でまとめると、**良いプロンプトとは、どこに境界線があるかをモデルに一意に伝えるプロンプト**である。言い回しの丁寧さや、背景の説明の量ではない。

優先度の高い順に並べる。

**1. 段階や条件を「状況」として定義する（最優先、特に順序ありの課題）**
Score で段階を数字（B1）や程度語（B2）にすると、MAE は約 0.23 悪化し、ECE は 2.5〜3 倍になった。"highly relevant" のような程度語は、順序は伝えても、どこからがその段階かを伝えない。A のように「一緒に使う別の品」「代わりになる別の品」と状況で書くと、境界が固定される。

**2. 質問文では、何を true とするかを具体的に書き、criteria と向きを揃える**
Noul B1 の「問題があるか」という曖昧な質問では、AUC は保たれたが、判定の境界がずれた（正解率 −26.7 ポイント、ECE 0.045→0.130）。また Noul B3 では、否定形の質問文（スパムでないか）と肯定形の criteria（true = スパム的）が矛盾しており、Jev は質問文に従って出力を丸ごと反転させた。少なくともこの 1 例では、質問文と criteria が食い違うと質問文が優先された。criteria を丁寧に書いても、質問文の誤りは救えない。

**3. 質問の意味が同じなら、言い回しには神経質にならなくてよい**
Choice と Score の B3（間接的な質問、無関係な評価軸の追加）では、精度も較正もほぼ変わらなかった。

**4. 判断に関係ない情報は state に入れない**
影響は小さいが、Score では有意だった（MAE +0.036、ECE 0.087→0.101）。入れて得することはないので、守って損はない。

**5. 選択肢の名前が自己説明的なら、説明は混同しやすいものに絞る**
Choice では、説明をすべて外しても（B1）精度も ECE も落ちなかった。ただし、BANKING77 の意図名（例：`card_arrival`）はそれ自体が説明的なので、名前が不透明な課題でも同じことが言えるかは分からない。

課題タイプ別に要約すると次のとおりである。

| 課題タイプ | 効いた要素 | 効かなかった要素 |
| --- | --- | --- |
| 順序なし多値分類（Choice） | 本実験では検出できず | 選択肢の説明、質問文、無関係な入力 |
| 順序あり分類（Score） | 段階を状況で定義すること（精度・較正とも） | 質問文の言い回し |
| 二値分類（Noul） | 質問文の具体性と、criteria との向きの一致（主に較正と閾値） | 条件の書き方、無関係な入力 |

### 4.5 反省と限界

**(1) ECE は事後に選んだ観点である。**
H3 は「確信度の高い誤答率」で判定する規則だったが、Jev の該当件数がほぼ 0〜2 件で、比較として機能しなかった（床効果）。dev で分布を確かめていれば、ECE や Brier スコアを主指標にできた。4.2〜4.4 節の所見は、次の実験で事前に宣言したうえで検証する必要がある。

**(2) ECE に区間も検定もない。**
付録「A 対 他条件」の confidence 行は平均確信度の差であり、較正の良し悪しを比べたものではない。60 件を 10 区間に分けると多くの区間は 0〜3 件になり、ECE は不安定で、上向きの偏りもある。次回は、対応のあるブートストラップで ECE の差の区間を出し、Brier スコアや対数損失でも比べるべきである。

**(3) Noul B3 は、質問文の効果を測れていない。**
否定形の質問文と、A と同じ肯定形の criteria が矛盾しており、正解ラベルも反転していない。この条件で測れたのは「質問文と criteria が矛盾したときにどちらが優先されるか」であり、「質問文を崩した効果」ではない。あわせて、3.3 節の表では Noul B3 を有意な悪化（0.996）として載せつつ、概要では「Noul で精度が大きく落ちた要素はなし」としており、記述が矛盾している。

**(4) 1 要素だけを変える設計になっていない条件がある。**
- Choice の A にだけ `other` がある。A の誤答 6 件はすべて「選択肢の重なり」で、`other` への誤振り分けは確認されなかった。それでも、B1・B2 との差には選択肢集合の違いが混ざっている。
- Noul B2 は定義を AND 条件にしており、書き方を崩したというより、判定対象そのものを変えている。
- Score B3 で足した「レビューの質・価格」は、state にその情報がなければ実質的に無視される操作である。

**(5) 標本が小さく、天井に近い。**
Choice と Noul は正解率が 0.9 を超えており、条件間の差は 1〜3 件分しかない。「差を検出できなかった」は「差がない」を意味しない。さらに Noul の test には、同じ本文のケースが 1 件重複している（一意なのは 59 件）。

**(6) 境界ケースを 50% 含む標本である。**
精度も ECE も、実運用の分布での値ではない。

**(7) 失敗の扱いが指標ごとに違う。**
呼び出しやパースの失敗は、正解率では不正解として数えるが、ECE では確信度が得られないため除外している（Choice L3 は 55 件、Score A は 59 件で計算）。失敗が多い条件ほど、ECE が実態より良く見える可能性がある。

**(8) 比較の公平性の問題。**
- Score の MAE は、Jev が丸めない連続値、LLM がラベルを写した整数である。中間の値を出すことが常に誤差として数えられるので、Jev に不利になる。
- Jev の確信度（分布の集中度）と LLM の自己申告は性質が違う量である。

**(9) H4 を判定できなかった。**
Jev のトークン数を記録しておらず、コストの比較ができなかった。

**(10) その他。**
各条件 1 回しか実行しておらず、再実行によるばらつきは測っていない。

## 5. 結論

ガイドに沿ったプロンプト（A）は、Jev の出力の精度を一様に上げたわけではない。しかし、確信度の較正は 3 課題すべてで良好だった（ECE 0.045〜0.087、Jev の条件の中で最小か同率最小）。

特に、順序ありの課題で段階を状況として定義すると、精度（MAE、段階の正解率）と較正の両方が改善した。二値の課題では、質問文を具体的にし、criteria と向きを揃えることが、較正と閾値の位置を保った。

以上から、Jev における良いプロンプトとは、判断の境界がどこにあるかを一意に伝えるものであり、その効果は主に「確信度をそのまま信じてよいか」に現れると考えられる。ただし、ECE による評価は事後に選んだ観点であり、ECE の差には区間が付いていない。Noul B3 の設計の不備も含め、これらは次の実験で事前に宣言したうえで検証する必要がある。

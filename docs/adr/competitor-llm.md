# ADR-0002 比較対象とする LLM の選定

主モデルに GPT-5.6 Luna、上限確認用に Claude Sonnet 5 を採用する。いずれも OpenRouter
経由で呼び出し、プロバイダを固定して再現性を確保する。DeepSeek 系の最安ホストと
`:free` モデルは、再現性と公開の観点から採用しない。

---

## 背景

評価設計書の条件 L1（素朴なプロンプト）と L2（整備したプロンプト）は、jev と比較する
LLM を前提にしている。このモデルをどれにするかが未決だった。

OpenRouter で使えること、費用を抑えられることが要望として挙がっている。あわせて、
実験結果はブログ記事として公開し、リポジトリも公開する（ADR-0001 参照）。

### 費用に関する前提の確認

先に実験全体の規模を見積もる。

| 項目 | 見積もり |
| --- | --- |
| LLM 呼び出し回数 | 3 課題 × 3 条件 × 100 ケース = 900、ばらつき測定で +1,200 |
| 入力トークン | 課題 1 が 77 意図のリストを毎回送るため最も重く、1 件あたり約 1,500。全体で約 150 万 |
| 出力トークン | 1 件あたり約 50、全体で約 10 万 |

この規模だと、$0.20 / $1.20 per 1M のモデルで **1 ドル未満**、$2 / $10 のモデルでも
**数ドル**で終わる。jev 側も $0.042 / 1M（出力は無料）なので同程度。

つまり費用はモデル選定の決め手にならない。選定基準は「読者にとって意味のある比較に
なるか」と「再現できるか」に置く。ただし記事で報告する 1,000 件あたりコストの数字は
モデルによって桁が変わるため、どのモデルを選んだかは結論の見え方に直結する。

---

## 判断基準

上から優先する。

1. **構造化出力の対応**：`response_format` の `json_schema` を `strict: true` で使える
   こと。出力形式が崩れると、プロンプト品質の差ではなくパース失敗を測ることになる
2. **再現性**：単一プロバイダに固定でき、量子化やルーティングで結果が揺れないこと
3. **読者にとっての意味**：「分類にこのモデルを使うのは自然だ」と読者が納得できること。
   無名のホスト経由の廉価モデルは、結論の説得力を下げる
4. **バージョン固定**：`-latest` のようなエイリアスではなく、日付付きのスラッグで
   固定でき、後から同じモデルを指定できること
5. **費用**：上記を満たしたうえで安いほうを選ぶ

---

## 検討した選択肢

価格は 2026-09-21 時点で確認したもの（per 1M tokens、入力 / 出力）。**OpenRouter の
価格は頻繁に変わるため、実行直前に models ページで再確認すること。**

| 候補 | 価格 | 評価 |
| --- | --- | --- |
| **GPT-5.6 Luna** | $0.20 / $1.20 | 2026-07-30 に約 80% 値下げ。大手ベンダーのモデルとしては最安の部類で、1M コンテキスト。構造化出力は一次対応。**主モデルに採用** |
| **Claude Sonnet 5** | $2 / $10 | 2026-08-10 から中位の標準。上限の確認用に L2 プロンプトのみ実行。**採用** |
| Gemini 3.8 Flash | $0.75 / $3.75 | 2026-09-02 リリース。現状 Luna より高い。2027-01-01 に値上げ予定との情報があり、公開後に記事の数字が古くなる |
| GPT-5.6 Terra | $2 / $12 | Sonnet 5 と同価格帯。どちらか一方で足りる |
| DeepSeek V4 Flash（第三者ホスト） | $0.05 / $0.16 前後 | 最安。ただし 30 以上のホストが並び、**ホストごとの量子化が開示されていない**。既定ルーティングは価格で選ぶため、同じリクエストが別のホストに飛ぶ。公開するベンチマークには使えない |
| `:free` モデル | $0 | 20 req/min・1 日 50〜1,000 件の制限があり、どのモデルが無料かは時期によって入れ替わる。数か月後に再現できない |

### 却下理由の詳細

**DeepSeek V4 Flash（および同種の廉価モデル）**

価格だけ見れば最有力だが、OpenRouter の既定ルーティングは直近 30 秒の稼働率と価格の
逆二乗で負荷分散するため、同一リクエストが別プロバイダに届く。ホストの量子化が
開示されていないので、測定したのがモデルの性能なのかホストの量子化の影響なのかを
分離できない。`provider.only` で 1 ホストに固定すれば回避できるが、そのホストが数か月後
も同じ設定で提供している保証はなく、公開する記事の再現手順としては弱い。

**`:free` モデル**

レート制限（20 req/min）だけでも 2,100 件の実行に 2 時間近くかかる。それ以上に、
無料枠のモデル構成が時期によって入れ替わるため、記事を読んだ人が同じ条件を再現できない。

**モデルを 1 つに絞る案**

安上がりではあるが、「jev はこの安いモデルより良い」だけだと、読者は「高いモデルなら
勝てるのでは」と考える。上限を 1 つ置くことでその問いに先に答えられる。追加コストは
数ドルなので、置かない理由がない。

## 決定

### 採用する構成

| 条件 | モデル | プロンプト | 目的 |
| --- | --- | --- | --- |
| L1 | GPT-5.6 Luna | 素朴 | 実際によく書かれる形での比較 |
| L2 | GPT-5.6 Luna | 整備 | プロンプトを揃えた公平な比較 |
| L3 | Claude Sonnet 5 | 整備 | 上限の確認 |

評価設計書の LLM 条件は L1 / L2 の 2 つだったが、L3 を追加して 3 条件とする。
条件数は 7 から 8 に増える。

### 呼び出し設定（全条件共通）

以下を設定しないと、測定しているものが変わってしまう。

```json
{
  "model": "openai/gpt-5.6-luna",
  "temperature": 0,
  "seed": 20260921,
  "provider": {
    "order": ["OpenAI"],
    "allow_fallbacks": false,
    "require_parameters": true,
    "data_collection": "deny"
  },
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "decision",
      "strict": true,
      "schema": { "...": "課題ごとのスキーマ" }
    }
  }
}
```

各設定の理由。

- `require_parameters: true` — **これが既定の `false` のままだと、構造化出力に対応
  しないエンドポイントにルーティングされた際にスキーマが黙って無視される**。結果、
  自由記述をパースすることになり、プロンプト品質ではなくパース成否を測ってしまう
- `allow_fallbacks: false` — 既定は `true` で、プロバイダ指定は「希望」にとどまる。
  `false` にして初めて固定になる
- `data_collection: "deny"` — 既定は `allow`。入力が学習に使われる可能性のある
  プロバイダに流れる
- `temperature: 0` と `seed` — 決定性は保証されない。経験的に検証する（下記）
- モデルスラッグは日付付きの固定版を使う。`~openai/gpt-luna-latest` のような
  エイリアスは実行時に解決先が変わる

### 記録する項目

評価設計書のログ項目に次を追加する。

- 実際に応答したプロバイダ（OpenRouter の生成メタデータから取得）
- 使用したモデルスラッグの完全な文字列
- 上記のルーティング設定一式

記事とリポジトリの README にもこの設定を載せる。推論スタックは実質的に
ハイパーパラメータであり、書かなければ再現できない。

## 影響

### jev 側も OpenRouter 経由にできる

jev は 2026-09-18 から OpenRouter で `typesafe/jev-1.13` として提供されている。
チャット用の `/chat/completions` ではなく、`POST https://openrouter.ai/api/alpha/decisions`
に送る。価格は $0.042 / 1M（入力）、出力は $0。

これを使うと API キーが 1 本で済み、コストとレイテンシを同じ経路で測れる。
一方で次の点に注意する。

- OpenRouter のモデルページはコンテキストを 32K と表示しており、TypeSafe のドキュメント
  の記述（1 リクエスト 64K、state と最長の質問で 32K）と揃わない。実行前に確認する
- alpha エンドポイントなので、仕様が変わる可能性がある
- **TypeSafe と直接契約しない場合、ADR-0001 で検討した MCA の適用関係が変わる**。
  適用されるのは OpenRouter の利用規約になる。ADR-0001 のパブリシティと秘密保持の
  論点を、この前提で読み直す必要がある

どちらの経路で jev を呼ぶかは本 ADR では決めない。別途判断する。

### jev はおそらく決定的ではない

OpenRouter のクックブックには、同一入力で呼び出しを繰り返すと確率が最大 0.08 程度
動いた例が記載されている（判定の結論自体は変わらなかった）。

評価設計書は「10 件で 2 回実行して決定性を確認し、一致しなければ全条件で 3 回実行して
平均を取る」としているが、**3 回実行する側になる前提で見積もっておく**。実行回数は
jev 側だけで 1,500 → 4,500 件になる。それでもコストは 1 ドル未満。

### 較正の比較は非対称になる

jev は確率分布を返すが、LLM は返さない。`logprobs` に対応するかはモデルとプロバイダに
依存するため、実行前に確認する。取得できなければ、LLM 側は JSON スキーマに含めた
自己申告 confidence で代用する。

この非対称性は隠さず、記事で明示する。自己申告 confidence が較正されていないこと自体が
比較の結果として意味を持つ。

### 価格が動くリスク

OpenRouter の価格は予告なく変わる。記事に絶対額を書かない方針（ADR-0001）は、
この点でも有利に働く。倍率で書いておけば、価格改定で記事が即座に古くならない。

ただし倍率も価格比なので、**測定日と、その日の両モデルの価格をリポジトリに記録**し、
記事では「2026-XX-XX 時点の価格に基づく」と断る。

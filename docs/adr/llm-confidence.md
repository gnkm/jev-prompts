# ADR-0003 LLM の確信度を確率分布から導出しない

本実験の LLM は `{"label", "confidence"}` の自己申告のままとする。確率の一覧を書かせ、そこから confidence を計算しても、Jev の分布と confidence にはならない。公開済みの `results/published.jsonl` には分布が無いので、LLM の ECE を確率から計算し直すこともできない。

モデル選定と、自己申告で代用する判断は [ADR-0002](competitor-llm.md) にある。本 ADR は、その代用を「分布から導出すれば Jev に近づく」と言い換えないための記録である。

## 背景

Jev の Choice と Score は、選択肢ごとの確率と、その分布の尖りを 0〜1 にまとめた `confidence` を返す。`confidence` は採用した答えが正しい確率ではない。想定されている使い方は、閾値で自動処理と人の確認を分けることである。Noul には `confidence` が無く、`noul` の値そのものが確率である。本実験では Noul の閾値信号に `max(p, 1 − p)` を使う。

比較用 LLM（L1〜L3）は `{"label", "confidence"}` だけを返す。この `confidence` はモデルが書いた数値である。集計コードはこの数を、LLM の ECE、Brier スコア、閾値信号の AUROC、risk-coverage、確信度の高い誤答率に入れられる。Jev では較正の確率と閾値の信号が別である。報告では、この数を Jev の較正や閾値と同じ表に置かない。

ADR-0002 は、非対称を隠さず、自己申告が較正されていないこと自体を比較の結果として残す、としていた。本 ADR はそこを改める。自己申告は較正の比較に使わない。`logprobs` が取れればモデル自身の確率を使う予定だったが、プロバイダ依存のため本実験では取っていない。

## 判断

分布を書かせて confidence を導出しても、Jev と同じ比較にはならない。

- 書かせた確率は自己申告のままである。トークンの確率でも、Jev が選択肢を個別に採点して得た分布でもない。ECE に載せる数の形は揃うが、出どころは揃わない。
- 公開されているデモの式 `(K × 最大確率 − 1) / (K − 1)` は、Jev の API が返す `confidence` と一致しない。同じ式を LLM の分布に当てても、Jev の閾値信号の再現にはならない。
- Choice は意図が 77 個ある。毎回フルの分布を書かせると、測っている作業が変わり、パース失敗も増える。Score の 4 段階と Noul の 2 値なら、出力の長さとしてはまだ現実的である。

したがって、本実験の報告は、LLM が自己申告の `confidence` を返すことと、それを較正と閾値の比較に使わないことだけを書く。分布が残っていないログから、LLM の ECE を確率へ置き換える再集計はしない。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **出力は自己申告のまま、報告では較正に使わない** | `{"label", "confidence"}`。主指標・トークン・レイテンシだけを Jev と並べる | **本実験の報告はこれ**。公開ログに分布は無い |
| 分布を書かせ、デモの式で confidence を計算する | スキーマを Jev の `probabilities` に似せ、尖りを式で作る | 却下。自己申告のままであり、その式は Jev の `confidence` と一致しない |
| 次の実験で出力を課題ごとに近づける | 下の三段階。本実験のログでは計算できない | 将来の別実験なら採れる。本実験の数には使わない |

次の実験でインターフェイスを近づけるときの定義は、次のとおりである。

- **Noul。** `spam` である確率を一つ返させる。Jev と同じく、別の `confidence` は置かない。
- **Choice と Score の較正。** 採用ラベルの確率を書かせ、ECE と Brier スコアはそれを使う。閾値の信号は、最大確率や 1 位と 2 位の差など、こちらで定義した尖りとして別に出す。Jev の `confidence` とは呼ばない。
- **モデル自身の確率。** ラベル集合上の `logprobs` を使う。ADR-0002 が最初に検討し、プロバイダ依存のため見送ったものである。Jev が選択肢を個別に採点する手続きそのものではない。

## 決定

- 本実験の LLM 出力は自己申告の `confidence` のままとする。
- 書かせた確率から計算した数を、Jev の `confidence` や Jev の確率と同じものとして報告しない。
- `results/published.jsonl` からの再集計で、LLM の ECE を確率に置き換えない。
- 報告では、LLM の自己申告から計算した ECE、Brier スコア、較正表、reliability diagram、閾値信号の AUROC、risk-coverage、確信度の高い誤答率を、Jev と同じ表に置かない。残すのは主指標、トークン数、レイテンシと、置かない理由の一文である。ECE と平均確信度の Holm 補正は A 対 B1・B2・B3・C の 4 比較だけをまとめて行い、主指標の補正は L1〜L3 との比較を加えた 7 比較をまとめて行う。
- 上の三段階を採るなら、新しい実行と、その実行のための Issue を分ける。`docs/source-of-truth/` の改定が要るなら、人間向けの別 Issue にする。

## 影響

- 報告の L1〜L3 は、主指標とトークン数とレイテンシである。自己申告の較正と閾値の数は、Jev の表に並べない。
- 分布を取る実行をしても、今回の 60 件の結果を遡って書き換えることはできない。
- 設計書は較正を `confidence` の 10 ビンと定義している。本 ADR は事後に選んだ較正の読み方を固定するものであり、設計書は変えない。
